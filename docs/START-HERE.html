Telegram Mini Apps — start here

8 apps · each = front end (Netlify) + its own Google Apps Script backend (its own API URL) + a Telegram bot.

Never put secrets (bot tokens, API keys, wallet private keys) in config.js, in chat, or in GitHub. They go only in Apps Script → Project Settings → Script properties and in Netlify → Environment variables.

Do this for each app (about 10 minutes per app)

  1. Backend. Go to script.google.com → New project. Rename it after the app. Delete the sample code, then create one file per .gs file in the app's apps-script/ folder (names as shown) and paste each file's contents.
  2. Script properties. Project Settings (gear) → Script properties → add ADMIN_IDS = your Telegram user ID (get it from @userinfobot) and the bot token as BOT_TOKEN_<app id>. AI apps also need GEMINI_KEY (from aistudio.google.com).
    Optional: to use ONE ledger for all apps, copy MASTER_SHEET_ID from the first project into the others before step 3.
  3. Install. Select the function install → Run → approve permissions. It creates the private master sheet and the daily/hourly jobs.
  4. Deploy the API. Deploy → New deployment → type Web app → Execute as Me → Who has access Anyone → Deploy. Copy the Web app URL (ends with /exec). This is the app's API — send it to Claude. It is not a secret.
  5. Bot. In Telegram open @BotFather → /newbot. Put the token only in Script properties (step 2) and Netlify (step 7). Optional: /newapp to get a short name for direct t.me/bot/app links (set botUsername + appShortName in config.js).
  6. Connect the bot. In the app's Apps Script file set THIS_APP.url to the app's Netlify URL, save, then run connectTelegram. It sets the webhook, the menu button and the commands.
  7. Netlify environment variables (site → Project configuration → Environment variables, mark secret): BOT_TOKEN, WEBHOOK_SECRET (copy WEBHOOK_SECRET_<app> from Script properties), SERVER_SECRET (copy from Script properties), GAS_URL (the /exec URL), APP_ID (the app id), APP_URL (the site URL).
  8. Link GitHub → Netlify so the bot webhook function deploys: site → Link repository → AXMED0111/1dc82a7c → base directory apps/<app id>, publish public, functions netlify/functions, no build command.
  9. Launch. Open the app as admin → Settings (sliders icon): set prices, USDT addresses, EVC/Zaad/Sahal numbers, then turn Test mode OFF.

Payments (already built in every app)

Starsglobal, main method · USDT TRC20 / BEP20unique amount per order, checked on-chain every 5 min (BEP20 needs ETHERSCAN_KEY) · EVC / Zaad / Sahal / M-Pesashown only to verified local numbers (+252 by default), admin approves in Settings.

Before launch, verify on Telegram's official pages: current Stars fees, payout via TON and hold period, and Apple's rules for in-app payments on iPhone (Stars is the safest option on iOS).

Engineering guide

Open ENGINEERING-GUIDE.md: architecture, security, health targets, playbooks for problems, launch checklist and the growth path. In every app: Settings → System health shows errors, speed, message queue, backups and webhook status; Maintenance mode pauses changes with one tap.

Testing before your backend is connected

With apiUrl empty each app runs in demo mode: everything works on the phone, data stays on that phone, payments are simulated. In Settings → Testing, turn on Simulate free user to see the free limit and the paywall.
